#+TITLE: Rexel

Rex multiplexer client for Emacs, built on [[https://github.com/dakra/ghostel][Ghostel]].

[[https://www.superlogical.com/rex][Rex]] is a terminal multiplexer: shells run in sessions on a Rex server and
keep running while no client is attached, as in tmux.  Rexel is a Rex
client for Emacs.  Each terminal of a session becomes a ghostel buffer with
a full terminal emulator, so typing, scrollback, search and copy mode work
as in a local terminal, and the shell keeps running on the server when
Emacs goes away.

The server can be this machine, or a remote one reached over Tailscale or
an ssh tunnel.  Rex.app, or any other Rex client, can be attached to the
same session at the same time.

- Attach to running sessions, create new ones, split and open tabs from Emacs.
- =M-x rexel= and =M-x rexel-project= in place of =M-x ghostel= and
  =M-x ghostel-project=: a session per project, a tab per terminal.
- Survives dropped connections, sleep and network changes.
- Drop or paste files onto a terminal to send them to the server's machine.
- Directory tracking and command state from the processes Rex reports.
- Your ghostel key bindings and settings apply in every block buffer.
- Optional pickers with previews and Embark actions, see [[*Consult and Embark][Consult and Embark]].

* Quick start

You need a Rex server (on macOS the Rex Beta app includes one) and, from
MELPA, ghostel and websocket.  Rexel itself is not on MELPA yet; on Emacs
30 and later:

#+begin_src emacs-lisp
(use-package rexel
  :vc (:url "https://github.com/dakra/rexel")
  ;; Session and block commands from any buffer
  :bind-keymap ("C-c C-r" . rexel-prefix-map)
  :custom
  ;; Show a session's focused block instead of asking what to show
  (rexel-attach-display 'focused)
  ;; A remote server, over Tailscale or an ssh tunnel to its socket
  (rexel-hosts '(("studio" "rex.tail1234.ts.net" "/tmp/studio.sock"))))
#+end_src

Only the =:vc= line is needed.  The others make the session and block
commands available everywhere under =C-c C-r= (in a block buffer they are
there anyway), skip the question which block of a session to show, and
name a remote server; this machine's server is found on its own.  See
[[*Servers][Servers]] for Tailscale and ssh.

On Emacs 29, =M-x package-vc-install RET https://github.com/dakra/rexel=;
on Emacs 28, clone the repository and add it to =load-path=.

Then =M-x rexel= shows a shell in a Rex session of its own, =M-x
rexel-new-session= starts a shell in a new session and =M-x rexel-attach=
picks a running one.  With no Rex server running, rexel offers to start
one.

* A first session

1. =M-x rexel-new-session= opens a shell in the buffer =*rex:SESSION:1*=,
   in the current directory.
2. =C-c C-r 3= splits it to the right with a second shell in the same
   directory; =C-c C-r c= opens a new tab.
3. A file dropped on the buffer is sent to the server's machine and its
   path typed into the terminal.
4. =C-c C-r d= detaches: the buffers go, the shells keep running.
5. Later, or from another Emacs, =M-x rexel-attach= brings the session back
   with its scrollback, and =C-c C-r == lays out the tab's blocks in the
   frame's windows.

The rest of this document covers each part in detail.

* Requirements

- Rex, for macOS, Linux or FreeBSD.  On macOS it comes with the Rex Beta app,
  which need not run; rexel looks for =rexel-program= on =exec-path=, then for
  the copy inside the app.  The app does not put =rex= on =PATH=; for use in a
  shell, symlink it:
  #+begin_src sh
  ln -s "/Applications/Rex Beta.app/Contents/Helpers/Rex Server.rex/Contents/MacOS/rex" /usr/local/bin/rex
  #+end_src
- A Rex server.  =M-x rexel-start-server= runs =rex server start= on this
  machine.  With no server known, rexel offers to do that; set
  =rexel-autostart-server= to =t= to skip the question or =nil= to never start
  one.  With systemd, =systemctl --user enable --now rex.socket= starts your
  own server on demand instead.
- [[https://github.com/dakra/ghostel][Ghostel]] 0.62.0 or later, with its native module.
- [[https://github.com/ahyatt/emacs-websocket][websocket]] 1.15 or later.
- Emacs 28.1 or later with native JSON support (=json-serialize=): built in
  since Emacs 30, libjansson on 28 and 29.
- For =consult-rexel=, [[https://github.com/minad/consult][consult]] 1.5 or later.  It uses [[https://github.com/oantolin/embark][Embark]] and
  =consult-ghostel= when they are installed.

* Servers

=M-x rexel-attach= and =M-x rexel-new-session= ask for a server when more
than one is known.  Servers are this machine's (from =rex server status=),
the hosts known to Rex (=rex hosts=) and =rexel-hosts=.

** Tailscale

A remote server is reached over Tailscale, which is built into Rex.  On
the server, =rex server tailscale on= joins it to your tailnet as a device
of its own; =rex server status= shows the sign-in link and then the
server's address.  =rex server start --tailscale= keeps it on across
restarts.  This machine needs Tailscale running under the same account.
Then add the host, which Rex and rexel both use:

#+begin_src sh
rex hosts add studio rex.tail1234.ts.net
#+end_src

** ssh

Without Tailscale, forward the server's socket over ssh.  For a Linux
server, with your user id on it in the path:

#+begin_src sh
ssh -N -o StreamLocalBindUnlink=yes \
    -L /tmp/devbox.sock:/run/user/1000/rex/server.sock devbox
rex hosts add devbox unix:///tmp/devbox.sock
#+end_src

=ssh devbox rex server status= prints the socket of a running server.  A
shared Linux server is at =/run/rex/server.sock= and a macOS one at
=~/Library/Application Support/rex/server.sock=.

** Without =rex= on this machine

Name the servers in =rexel-hosts= instead:

#+begin_src emacs-lisp
(setq rexel-hosts
      '(("studio" . "rex.tail1234.ts.net")
        ("devbox" . "/tmp/devbox.sock")
        ;; Tried in order; a redial starts with the one that last answered
        ("laptop" "rex.tail5678.ts.net" "http://192.168.1.20:7297")))
#+end_src

An address without a scheme is reached over https only; =http://HOST:PORT=
names a plain listener.  A host alone, without port or path, is tried on
its scheme's port, then on Rex's port 7297.  An entry replaces a host of
the same label known to Rex.  Buffers of a host are named
=*rex:SESSION@HOST:TAB*=.

* Sessions

=M-x rexel-attach= lists a server's sessions and opens one ghostel buffer
per terminal block.  For a session of several blocks it then asks what to
show: a block, named after its tab and the program and directory running
in it, with the focused one first, or a tab's layout.  A block pops up and
leaves your windows as they are; the layout of a tab with a split rebuilds
the frame's windows from it, as =rexel-sync-layout= does.
=rexel-attach-display= set to =focused= shows the focused block without
asking, and =layout= the active tab's layout; =C-u M-x rexel-attach= asks
whatever it is set to.

A block buffer is named =*rex:SESSION:TAB*=, after its session and the
label of its tab, or the tab's number when it has no label.  The other
blocks of a split tab are =TAB.2=, =TAB.3= and so on.  The names follow the
tabs: closing a tab renumbers the buffers of those after it.

=M-x rexel-new-session= creates a session with one shell and attaches to
it, asking for its label with a prefix argument.  On this machine's server
the shell starts in =default-directory=, elsewhere in the home directory.
=rexel-session-label-function= rewrites the label of every new session.

Killing a block buffer closes its block and ends the program in it, after
a confirmation when the block runs a command.  With
=rexel-kill-buffer-action= set to =keep= the block keeps running, and =ask=
asks each time.  This holds for every kill, also one by
=project-kill-buffers= or =clean-buffer-list=.  =C-c C-r d= detaches from the
whole session and leaves it running.  A session whose last block closed
stays on the server, empty.

* In place of ghostel's commands

=M-x rexel= is to Rex what =M-x ghostel= is to a local terminal.  It shows
the session labelled =emacs= (=rexel-default-session=) on this machine's
server, in the selected window, and creates it with a shell in
=default-directory= when the server has none.  In a TRAMP directory the
server is another, see [[*Other machines][Other machines]].  A terminal is a tab of that
session:

| Command           | Shows                                              |
|-------------------+----------------------------------------------------|
| =M-x rexel=         | the block you selected last, else the focused one  |
| =C-u M-x rexel=     | a new tab, its shell in =default-directory=          |
| =C-u 2 M-x rexel=   | tab 2, or a new tab when the session has no tab 2  |

The session outlives Emacs, so after a restart =M-x rexel= is back in the
shells you left.  A session without a block left gets a new tab.

** Projects

=rexel-project=, in =rexel-project.el=, does the same with one session per
project, labelled with the project's name:

#+begin_src emacs-lisp
(use-package rexel-project
  :bind (:map project-prefix-map
         ("m" . rexel-project)
         ("M" . rexel-project-new)
         ;; In place of project-kill-buffers
         ("k" . rexel-project-kill))
  :init
  (with-eval-after-load 'project
    (add-to-list 'project-switch-commands '(rexel-project "Rexel") t)))
#+end_src

- =M-x rexel-project= shows the project's session and creates it with a
  shell in the project's root.  It takes the prefix arguments of =M-x rexel=.
- =M-x rexel-project-new= opens another tab at the project's root.
- =M-x rexel-project-kill= runs =project-kill-buffers=, which asks first, and
  then destroys the project's session with its programs, also when this
  Emacs is not attached to it.  A session with blocks that run a command
  asks first, and so does a project without buffers to kill.  No server
  is started for it.

The session is found by its label, so two projects of one name share a
session, and a session renamed in another client is no longer the
project's.  The name is the one project.el gives the project;
=project-vc-name=, set in =.dir-locals.el=, changes it.

** Other machines

In a TRAMP directory =M-x rexel= and the project commands use the Rex
server of that machine:
a project at =/ssh:studio:/srv/app/= has its session on the server
labelled =studio=, or whose address names the host =studio=, and its shell
starts in =/srv/app= there.  A machine without a known server is an error,
and a TRAMP directory on this machine, as under =/sudo::=, uses this
machine's server.  =rexel-tramp-hosts= names the server for a TRAMP prefix
that neither matches:

#+begin_src emacs-lisp
(setq rexel-tramp-hosts '(("devbox" . "/ssh:daniel@box.example.org:")))
#+end_src

The buffers of such a server's blocks follow their shells' directories
under the prefix, so =find-file= in one starts there.

=project-kill-buffers= itself leaves the sessions alone: by default it
kills no ghostel buffer.  Ghostel's README has the condition that makes
it kill them, which closes the blocks of a project and leaves its
session empty.

* Key bindings

In a block buffer =C-c C-r= (=rexel-prefix-key=) prefixes:

| Key        | Command                                      |
|------------+----------------------------------------------|
| ~3~        | ~rexel-split-right~                          |
| ~2~        | ~rexel-split-below~                          |
| arrow keys | split to that side, e.g. ~rexel-split-left~  |
| ~RET~      | ~rexel-split~, below or right, where it fits |
| ~c~        | ~rexel-new-tab~                              |
| ~a~        | ~rexel-attach~                               |
| ~n~        | ~rexel-new-session~                          |
| ~=~        | ~rexel-sync-layout~, see [[*Layout and size][Layout and size]]       |
| ~$~        | ~rexel-rename-session~                       |
| ~u~        | ~rexel-upload-file~, see [[*Uploading files][Uploading files]]       |
| ~x~        | ~rexel-close-block~, ends the program        |
| ~d~        | ~rexel-detach~, keeps the session running    |

A split or tab's shell starts in the directory of the current block's
shell.

The map is =rexel-prefix-map=.  Bound globally, as in the [[*Quick start][Quick start]],
its ~a~, ~n~ and ~=~ work in any buffer and ~u~ in Dired, where it sends the
marked files to a block buffer you pick; the other commands need a block
buffer.  Modes that bind =C-c C-r= themselves, such as Org, Python and
Magit, keep it.  To move the prefix in block buffers, customize
=rexel-prefix-key=:

#+begin_src emacs-lisp
(setopt rexel-prefix-key "C-c b")
#+end_src

All other keys behave as in any ghostel buffer.

* Layout and size

Emacs windows are not kept in step with the Rex layout.  ~rexel-sync-layout~
rebuilds the selected frame's windows from the current block's Rex tab,
with ~C-u~ from a tab picked by label; outside a block buffer it asks for an
attached session and uses its active tab.  Only the tab's tiled layout is
rebuilt: a block floating above it is an ordinary buffer to switch to,
marked floating or minimized when =rexel-attach= lists it, and a tab of
floating blocks alone shows its focused one.  Rex's zoom is not mirrored;
=C-x 1= on a block does the same here.

Emacs takes ownership of a block when a window starts showing it or its
stream reconnects, so the terminal is sized to the smallest Emacs window
showing it, as a tmux client would.  A window that starts showing a block
while you are in the minibuffer, as the preview of a buffer picker does,
takes it only if it still shows it once the minibuffer exits.  Another client such as Rex.app can
take the block back; the terminal then follows that client's size until
Emacs takes it again.  With the keyboard focus Emacs does so for the block
in the selected window: when you select that window, when it changes size,
and when the frame gets the focus.  A terminal that does not report its
focus counts as focused.  While another client sizes the block, its mode
line reads =[Sized by another client 183x138]= with the size that client
gave it, and =mouse-1= on that takes the block too.

* Consult and Embark

Block buffers are ghostel buffers, so the buffer pickers list them.
=consult-rexel=, in =extensions/consult-rexel/=, adds pickers of its own on
top of [[https://github.com/minad/consult][consult]]:

#+begin_src emacs-lisp
(use-package consult-rexel
  :vc (:url "https://github.com/dakra/rexel"
       :lisp-dir "extensions/consult-rexel")
  :hook (after-init . consult-rexel-mode)
  :bind (("C-x m" . consult-rexel)
         :map project-prefix-map
         ("m" . consult-rexel-project)
         :map rexel-prefix-map
         ("r" . consult-rexel)
         ("t" . consult-rexel-tab)))
#+end_src

The mode loads rexel and consult when Emacs starts.  =consult-rexel= and
=consult-rexel-tab= are then also on =C-c C-r r= and =C-c C-r t=: in a block
buffer, and everywhere with the =:bind-keymap= line of the [[*Quick start][Quick start]].

- =M-x consult-rexel= lists the block buffers, grouped by session, and
  below them the other sessions of the connected servers.  In a project
  on this machine its session comes first.  A block is previewed as its
  buffer, and a session by the end of the text in its focused block,
  without attaching to it.  Choosing a session attaches it as
  =rexel-attach= does.  A name that matches nothing opens a tab with that
  label in the session of =M-x rexel=, and the /New/ group offers such a
  tab and a new session.  Without a connection, or with =C-u=, it connects
  to a server first.  Listing the sessions subscribes the connection to
  the session events of the whole server.
- =M-x consult-rexel-project= lists the blocks of the current project's
  session, which it attaches to first.  A name that matches nothing opens
  a tab with that label in it, and creates the session when the server
  has none.  With a prefix argument it is =rexel-project=.
- With =consult-ghostel= installed both list what =consult-ghostel= and
  =consult-ghostel-project= list as well, so they can take the place of
  those commands.  Each Rex block is listed once, under its session; in
  =consult-rexel-project= a block of another session that is in the
  project's directory stays with ghostel's.  The narrow key =r= shows the
  Rex groups alone.  =consult-rexel-sources= and
  =consult-rexel-project-sources= hold the sources.
- =M-x consult-rexel-tab= picks a tab of a session and rebuilds the
  frame's windows from it, previewing each layout in the selected window.
- =consult-rexel-mode= adds the blocks to =consult-ghostel= and
  =consult-buffer= as a hidden source.  The narrow key =r= shows it alone,
  as in =consult-rexel=; in =consult-buffer=, where =r= shows the registers,
  the key is =x=.  The mode also gives the prompts of =rexel-attach= and
  =C-u M-x rexel-sync-layout= the same previews of blocks and layouts.

With [[https://github.com/oantolin/embark][Embark]] installed the mode also adds actions.  On a buffer, in any
buffer prompt, =R= (=consult-rexel-embark-key=) prefixes the actions on a
Rex block: =R d= detaches its session, =R x= closes the block and =R $=
renames the session, the keys of =C-c C-r=.  On a session in
=consult-rexel=, =a= attaches, =d= detaches, =$= renames and =k= destroys it.

* Uploading files

A file dropped on a block buffer, or an image pasted with =M-x yank-media=,
goes to the program in the block: Rexel sends the file to the server's
machine and Rex types its path into the terminal, as a paste.  This is how
to hand a screenshot to a coding agent running in a remote block, for
example.

~rexel-upload-file~ (=C-c C-r u=) does the same for a file read from the
minibuffer.  In a Dired buffer it sends the marked files to a block buffer
you pick.  Files on a TRAMP host are fetched first, which Emacs waits for
and which cannot be cancelled.

Files sent together have their paths typed together, in order, once all
have arrived.  The server keeps them until the block closes.  It takes
files of up to 100 MiB, 16 at a time; more than 16 go in rounds.  Emacs
stays usable while a file is sent and ~rexel-cancel-upload~ stops it.  While a
connection stalls Emacs waits, and gives the upload up after ten seconds; each
stalled connection can take that long in turn, one carrying a large paste
longer.  A cancelled upload, or one whose connection drops or stalls, types
nothing and is not resumed.

The exception is this machine's server: a local file is not copied, and
Rexel types its own path.

* Shell integration

The Rex server starts the shell of a block, so ghostel cannot inject its
shell integration.  Rexel reads the processes Rex reports instead:
=default-directory= follows the shell's working directory on this machine's
server and on one with a TRAMP prefix (see [[*Other machines][Other machines]]),
and =ghostel-command-running-p= knows when a command runs.  Rex
reports process changes with some delay, so a command that finishes within
a moment can go unseen.

Prompt navigation (=C-c M-n= / =C-c M-p=), exact command boundaries and
=ghostel cmd= need the shell to emit ghostel's escape sequences.  Rex sets
=TERM_PROGRAM=rex=, so source the integration on that too:

#+begin_src sh
# ~/.bashrc
if [[ "${INSIDE_EMACS%%,*}" = ghostel || "$TERM_PROGRAM" = rex ]]; then
    source /path/to/ghostel/etc/shell/ghostel.bash
fi

# ~/.zshrc
if [[ "${${INSIDE_EMACS-}%%,*}" = ghostel || "$TERM_PROGRAM" = rex ]]; then
    source /path/to/ghostel/etc/shell/ghostel.zsh
fi

# ~/.config/fish/config.fish
if string match -qr '^ghostel(,|$)' -- "$INSIDE_EMACS"; or test "$TERM_PROGRAM" = rex
    source /path/to/ghostel/etc/shell/ghostel.fish
end
#+end_src

Nushell emits OSC 7 and 133 itself; see ghostel's README for its
=ghostel.nu=.  Sourcing the scripts is harmless when the block is shown in
Rex.app, which uses the directory report and ignores the rest.

| Option                       | Default   | Meaning                                                |
|------------------------------+-----------+--------------------------------------------------------|
| =rexel-hosts=                  | =nil=       | Servers besides those =rex= knows, see [[*Servers][Servers]]           |

| =rexel-default-session=        | ="emacs"=   | Label of the session =M-x rexel= shows                   |

in each new one.

* Status

Attaching, typing, resizing, uploads and the basic layout commands work.

A dropped data connection resumes its stream, and a lost control
connection is redialled with backoff while sessions are attached; typing
meanwhile is sent once it is back, but keys on their way when the
connection dropped may be lost.  A connection that stays silent is pinged
and counts as dropped when the server does not answer, so a link left dead
by a sleep or a network change recovers too.

* How it works

Rex streams each terminal to its clients as a libghostty snapshot followed
by the raw PTY bytes.  Ghostel runs libghostty, so Rexel feeds that stream
straight into a ghostel buffer's terminal engine instead of emulating a
terminal of its own; keystrokes travel back over Rex's control API.  Both
connections are WebSockets, on the server's Unix socket or its network
address.
