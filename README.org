#+TITLE: rexel

Rex multiplexer client for Emacs, built on [[https://github.com/dakra/ghostel][ghostel]].

[[https://www.superlogical.com/rex][Rex]] streams each terminal to its clients as a libghostty snapshot
followed by the raw PTY bytes.  ghostel runs libghostty, so rexel feeds
that stream straight into a ghostel buffer: scrollback, search, copy mode
and key encoding work as in a local terminal, and the session keeps
running on the Rex server when Emacs goes away.

Prototype status: attaching, typing, resizing and the basic layout
commands work.  A dropped data connection resumes its stream, and a lost
control connection is redialled with backoff while sessions are attached;
typing meanwhile is sent once it is back.  Colors follow the Emacs theme
as in any ghostel buffer; the theme set in Rex is not applied.

* Requirements

- A running Rex server (the Rex app on macOS, or =rex server= on Linux).
- ghostel 0.60.0 or later with a native module built from a source that
  has =ghostel--restore-snapshot=.
- [[https://github.com/ahyatt/emacs-websocket][websocket]] 1.15 or later.
- Emacs with native JSON support (=json-serialize=): built in since Emacs 30,
  libjansson on 28 and 29.

* Usage

=M-x rexel-attach= asks for a server when more than one is known, lists its
sessions and opens one ghostel buffer per terminal block.  Servers are this
machine's (from =rex server status=), the hosts known to Rex (=rex hosts=)
that have a Unix socket endpoint, and =rexel-hosts=.

=M-x rexel-new-session= creates a session with one shell and attaches to it,
asking for its label with a prefix argument.  =rexel-session-label-function=
can rewrite the label; this one names a session after the current project
unless another label was given:

#+begin_src emacs-lisp
(setq rexel-session-label-function
      (lambda (label)
        (if-let* ((p (and (string-empty-p label) (project-current))))
            (project-name p)
          label)))
#+end_src

A remote server is reached through an ssh forward of its socket, which
Rex and rexel then both use:

#+begin_src sh
ssh -N -o StreamLocalBindUnlink=yes \
    -L /tmp/studio.sock:/Users/me/Library/Application\ Support/rex/server.sock studio
rex hosts add studio unix:///tmp/studio.sock
#+end_src

Without =rex= on this machine, name the socket in =rexel-hosts= instead:
=(setq rexel-hosts '(("studio" . "/tmp/studio.sock")))=.  Buffers of a
host are named =*rex:SESSION@HOST:ID*=.

In a block buffer =C-c C-r= (=rexel-prefix-key=) prefixes:

| Key        | Command                                      |
|------------+----------------------------------------------|
| ~%~ or ~3~ | ~rexel-split-right~                          |
| ~"~ or ~2~ | ~rexel-split-below~                          |
| arrow keys | split to that side, e.g. ~rexel-split-left~  |
| ~RET~      | ~rexel-split~, below or right, where it fits |
| ~c~        | ~rexel-new-tab~                              |
| ~=~        | ~rexel-sync-layout~, see below               |
| ~$~        | ~rexel-rename-session~                       |
| ~x~        | ~rexel-close-block~, ends the program        |
| ~d~        | ~rexel-detach~, keeps the session running    |

Killing a block buffer only closes the stream; the block keeps running.

Emacs windows are not kept in step with the Rex layout.  ~rexel-sync-layout~
rebuilds the selected frame's windows from the current block's Rex tab,
with ~C-u~ from a tab picked by label; outside a block buffer it asks for an
attached session and uses its active tab.
Floating blocks and zoom are ignored.

Emacs takes ownership of a block when a window starts showing it or its
stream reconnects, so the terminal is sized to the smallest Emacs window
showing it, as a tmux client would.  Another client such as Rex.app can
take the block back; the terminal then follows that client's size until
Emacs takes it again.

* Development

=make= byte-compiles, runs the tests and lints.  The tests cover the stream
parsing; everything else needs a live server.
